Realtime Fraud Detection Pipeline

A live deployment of an event-time fraud scoring system: Kafka ingestion, checkpointed PyFlink scoring, an authenticated analyst feedback API backed by a transactional outbox, guarded online model updates with MLflow promotion, and Prometheus and Grafana monitoring. A generator publishes synthetic transactions continuously, so every surface below carries live data.

Suggested walkthrough

  1. Open the Grafana dashboard and confirm transactions are being scored and a share of them routed as anomalies.
  2. Check Flink cluster status to see the streaming job running with checkpointing enabled.
  3. Submit analyst feedback through the API console using the request below. Send it twice with the same Idempotency-Key to confirm duplicate acceptance is exactly-once.
  4. Return to Grafana and watch the feedback counter, the outbox drain, and the online update metrics respond.
  5. Open MLflow to see whether the candidate cleared the promotion guardrails and took the champion alias.

Submitting feedback

Replace API_KEY with the key supplied with this demo, and HOST with this page's address.

curl -X POST http://HOST/api/feedback \
  -H "Content-Type: application/json" \
  -H "X-API-Key: API_KEY" \
  -H "Idempotency-Key: demo-001" \
  -d '{
    "anomaly_id": "demo-anomaly-001",
    "label": "true_positive",
    "analyst_id": "evaluator",
    "features": {}
  }'

The API commits the feedback row and its outbox row in a single Postgres transaction before it acknowledges. The relay publishes to Kafka with an idempotent producer and acks=all. The updater stages an SGD candidate and promotes it only after it clears the quality gates.

Demo deployment. Traffic is synthetic and no real transaction data is present. Transport is unencrypted HTTP and the stack is intended to be reachable only for the duration of an evaluation.
